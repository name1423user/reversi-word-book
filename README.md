# リバーシ単語帳

表・裏どちらにも画像を入れられるフラッシュカード単語帳アプリ。PC・iPad・iPhoneで動く、ローカル完結のPWAです。

`docs/flashcard-spec.md` の構想ドキュメントをもとに実装しています。

## 機能概要

- **デッキ機能**：複数の単語帳（デッキ）を作成・名前変更・削除・並び替え（手動↑↓／名前／枚数／作成日）
- **入力画面**：表裏それぞれにテキスト＋画像1枚。画像はドラッグ＆ドロップ／クリップボードペースト／URL指定に対応し、アップロードした画像はトリミング後にWebPへ圧縮。入力中の内容は自動保存（デバウンス）され、一覧から検索・並び替え・編集ができる
- **AIでカード作成**：入力画面から、勉強資料をAI（ChatGPTなど）に渡してカードを自動生成させるためのプロンプトをコピーできる。枚数と形式（用語→意味／問い→答え／穴埋め）を選ぶとプロンプトが変わる
- **カード管理**：カードの複製、複数選択しての一括削除、正答率バッジ、「苦手順」ソート
- **JSON一括登録／エクスポート**：`front/frontImage/back/backImage` の配列JSONを貼り付け・ファイル読み込みで一括登録（追加／置き換えを毎回選択、表テキストの重複はスキップ可能）。書き出しは「画像込み」「テキストのみ」の2モード、さらに全デッキを1ファイルにまとめるバックアップにも対応
- **フラッシュカード画面**：中央タップで裏返し、左右の端タップ／スワイプで正解・不正解を判定。キーボード（← → スペース）にも対応し、判定は複数回まとめて取り消せる。ラウンド内・通算の進捗表示、出題順の選択（シャッフル／順番どおり／苦手優先）、初回のみの操作ガイド付き
- **一周終了後のサマリー**：正解率・所要時間・直近セッションとの比較・最大連続正解・一番迷ったカード・間違えたカード一覧を表示し、「不正解だけ再挑戦（再帰的）」「最初からやり直す」「終了する」を選択可能
- **継続記録**：デッキ単位のストリーク（連続学習日数）とカレンダー表示、全デッキ横断のダッシュボード（総枚数・全体ストリーク・GitHub草型ヒートマップ）
- **ダークモード**：システム設定に自動追従＋手動切り替え
- **PWA**：ホーム画面に追加してオフラインでも利用可能

データはすべて端末内（IndexedDB／localStorage）に保存され、外部サーバーとの通信は行いません（画像URLを外部指定した場合を除く）。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm run build     # 型チェック + 本番ビルド
npm run preview   # ビルド結果のプレビュー
npm run lint      # oxlint
npm test          # vitest（単体テスト）
npm run test:e2e  # Playwright（E2E。ブラウザ未取得なら npx playwright install chromium）
node scripts/gen-icons.mjs  # PWAアイコンの再生成
```

pushとPull RequestではGitHub Actions（`.github/workflows/ci.yml`）がlint・単体テスト・型チェック・ビルドとE2Eを実行します。

独自のChromiumを持つ環境では `PLAYWRIGHT_CHROMIUM_PATH=/path/to/chromium npm run test:e2e` のように実行パスを指定できます。

## 実装メモ・仕様上の判断

構想メモの中で未確定/実装判断が必要だった点は次のように決めました：

- **通算プログレス**：セッション開始時のカード枚数を起点とし、「不正解だけ再挑戦」で新しいラウンドを始めるたびにそのラウンドの枚数を通算の分母に追加していく方式にしています
- **直近セッションとの比較**：デッキごとに「そのセッションの最初のラウンド」の結果のみを学習記録（ストリーク用）として保存し、サマリー画面の比較対象にしています。不正解だけの再挑戦ラウンドは記録を上書きしません
- **画像トリミング**：アップロード／ペーストした画像のみトリミング対象。URL指定の画像はそのまま使用します（外部画像はCORSの都合上トリミングできないため）
- **画像の保存方式**：アップロード画像はbase64データURLとしてカード行に埋め込まず、Blobとして別テーブル（`images`）に保存し、カードは`image:<id>`という参照のみを持ちます。base64は元データより約33%大きくなるため、これによりIndexedDBの行を小さく保てます。カード削除・デッキ削除・JSON一括置換・画像の削除や差し替えのたびに対応するBlobを削除し、加えてアプリ起動時に「どのカードからも参照されていないBlob」を一括削除するセーフティネットも動かしています（下書き段階で画像だけアップロードして保存しなかった場合などの取りこぼし対策）。JSON書き出し／読み込みの境界では、この内部参照をspec通りのポータブルな形式（外部URLまたはWebPのdata URL）に変換しています
- **Undo**：現在のラウンド内で、直前の判定から遡って複数回取り消せます（ラウンドをまたいだUndoは行いません）
- **初回ガイド**：全デッキ共通で一度だけ表示し、フラッシュカード画面右上の「?」ボタンからいつでも再表示できます
- **苦手優先の出題順**：`history`から算出したスコア（正答率・直近の不正解・迷った時間）の高い順に出題します。未学習のカードは「いつも間違えるカード」より下、「いつも正解するカード」より上に来るようにしています
- **エクスポートと画像**：構想メモのJSON形式は画像を「URL または WebPデータ」と定めているため、内部の`image:<id>`参照は書き出し時にdata URLへ戻します。「画像込み」モードでは外部URLの画像も可能な範囲でfetchして取り込みますが、CORSで取得できないものはURLのまま残し、その件数を表示します。端末移行には全デッキを1ファイルにまとめるバックアップを使ってください（ZIPも検討しましたが、iPhone/iPadでAirDropやファイルアプリ経由で扱いやすい単一JSONにしています）
- **AI生成プロンプト**：アプリ自体はAIを呼びません（APIキー不要・ローカル完結のまま）。代わりに、JSON一括登録がすでに受け付けている形式をそのまま出力させるプロンプトを配るだけにしました。画像はAIが正しい値を作れないため必ず`null`にさせ、画像はあとからアプリ側で追加する前提です。プロンプトには「資料に書かれていないことは書かない」というルールを明示しています（学習用途では捏造が一番害が大きいため）。またAIの返答は`\`\`\`json`で囲まれたり前置きが付いたりするのが普通なので、取り込み側でそれらを剥がしてから解析します
- **同期**：バックエンドは持たず、バックアップJSONの書き出し／読み込みによる手動同期としています。読み込みは常に新しいデッキとして追加するため、既存のデッキを壊しません
- **データの永続化**：iOS SafariはしばらくアクセスがないサイトのIndexedDBを削除することがあるため、保存データがある状態で永続化されていない場合に警告バナーを出します。ホーム画面に追加したPWAはこの削除の対象外なので、iOSではその案内を優先し、それ以外のブラウザでは`navigator.storage.persist()`を要求するボタンを出します。ページ読み込み時に自動で`persist()`を呼ばないのは、Firefoxで無説明の権限ダイアログが出るのを避けるためです
- **保存失敗の扱い**：容量オーバー（`QuotaExceededError`）などで書き込みに失敗した場合、黙って失敗せず画面下部に理由と対処（バックアップを取ってから不要なカードを削除する）を表示します。Dexieは元のエラーを`inner`に包むため、判定はそこまで辿って行います
